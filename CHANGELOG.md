### Fixed
Beberapa isu ditemukan & diperbaiki selama setup Fase 1 — dicatat di sini supaya tidak terulang di fase berikutnya:
- **Plugin SQL tidak terdaftar di `lib.rs`**: `npm run tauri add sql` sempat hanya menambah dependency di `Cargo.toml` tanpa ikut menyisipkan `.plugin(tauri_plugin_sql::Builder::default().build())` di `src-tauri/src/lib.rs`. Ditambahkan manual.
- **Paket JS `@tauri-apps/plugin-sql` belum ter-install**: sisi Rust (`Cargo.toml`) dan sisi JS (`package.json`) adalah dua instalasi terpisah untuk plugin yang sama — keduanya wajib ada. Diinstall manual via `npm install @tauri-apps/plugin-sql`.
- **`npx tailwindcss init -p` gagal ("could not determine executable to run")**: command `init` sudah dihapus total di Tailwind CSS v4. Diganti dengan pendekatan plugin Vite resmi (`@tailwindcss/vite` + `@import "tailwindcss";` di CSS, tanpa `tailwind.config.js`).
- **`table roles already exists` saat startup**: root cause race condition dari `React.StrictMode` yang menjalankan `useEffect` dua kali di development, menyebabkan migration terpanggil dua kali hampir bersamaan sebelum `PRAGMA user_version` sempat ter-update. Diperbaiki dua lapis: (1) `src/database/db.ts` men-cache **Promise** inisialisasi (bukan hasil resolved-nya) supaya panggilan concurrent menunggu proses yang sama; (2) semua statement di migration diubah jadi idempotent (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`).
- **ESLint tidak ter-install**: scaffold `create-tauri-app` versi ini tidak otomatis menyertakan ESLint. Dipasang manual dengan **flat config** (`eslint.config.js`) — bukan `.eslintrc.cjs` (format lama, sempat salah disarankan di awal).
- **`vitest run` exit code 1 saat belum ada test**: default Vitest menganggap "no test files" sebagai kegagalan. Ditambahkan flag `--passWithNoTests` di script `test`.
- **File nyasar `src-tauri/2`**: file kosong tidak sengaja ke-generate (kemungkinan dari output redirect yang salah ketik di salah satu command sebelumnya), sempat ikut ter-commit. Dihapus.
- **`.gitignore` ada baris menyatu**: `*.local` dan `src-tauri/target/` sempat ke-paste jadi satu baris (`*.localsrc-tauri/target/`), membuat pattern `*.local` tidak match apa pun. Diperbaiki jadi dua baris terpisah. (`src-tauri/target/` tetap aman karena ada `src-tauri/.gitignore` bawaan Tauri.)

- **`cargo add argon2` mengambil versi RC (0.6.0) yang API-nya tidak stabil**, menyebabkan 3 ronde error compile berantai (`unresolved import SaltString/rand_core`, perubahan signature method, `OsRng` gated di belakang fitur `getrandom`). Diperbaiki dengan pin eksplisit `argon2 = { version = "0.5.3", features = ["std"] }`.
- **Migration runner (`src/database/migrate.ts`) diam-diam skip statement SQL yang didahului baris komentar `--`**: pemisahan statement pakai `split(";")` lalu filter `!s.startsWith("--")` — kalau satu "potongan" antara dua `;` diawali baris komentar (walau ada SQL nyata di baris setelahnya dalam potongan yang sama), SELURUH potongan ikut ter-skip tanpa error. Ini menyebabkan seed `INSERT INTO roles` tidak pernah jalan (tabel `roles` kosong) padahal migration "berhasil" tanpa pesan error apa pun. Diperbaiki dengan membuang semua baris komentar dari SQL SEBELUM dipecah per statement (fungsi `stripComments`), bukan filter per-potongan setelah dipecah.
- **`repository.ts` modul auth salah asumsi kolom**: query memakai `r.code`/`WHERE code = $1` padahal tabel `roles` di migration menyimpan nama role di kolom `name`, bukan `code` (beda dari tabel `permit_status` yang memang pakai `code`). Diperbaiki jadi `r.name as role_code` / `WHERE name = $1`.
- **Tailwind CSS tidak ter-load setelah `App.tsx` ditimpa total di Fase 2**: baris `import "./App.css"` (atau `./index.css`, tergantung di file mana `@import "tailwindcss";` diletakkan) ikut hilang saat isi `App.tsx` diganti untuk alur setup/login, sehingga file CSS yang berisi Tailwind tidak pernah di-import lagi. Diperbaiki dengan memastikan baris import CSS tetap ada di entry point yang benar-benar dirender.
- **`LoginPage` tidak redirect setelah login sukses**: `setUser(user)` dipanggil tapi tidak ada `navigate("/")`, jadi user tetap terlihat "stuck" di halaman login walau autentikasi sebenarnya berhasil. Diperbaiki dengan `useNavigate()` dari `react-router-dom`.
- **ESLint `react-hooks/set-state-in-effect` menolak pola `useEffect(() => { load() }, [])` untuk data-fetching** (aturan React terbaru). Diperbaiki dengan migrasi ke TanStack Query (`useQuery` + `invalidateQueries`) di `PermitTypesPage`/`PermitTypeDetailPage` — pola ini yang dipakai seterusnya untuk semua data-fetching halaman baru, bukan `useEffect` manual.
- **PostCSS error "@import statements must precede all other statements"** muncul di Fase 4 walau urutan `@import` di `index.css` sudah benar sejak awal file. Root cause: `@import url(...)` untuk Google Fonts digabung dengan `@import "tailwindcss";` (yang di-expand jadi banyak sub-import oleh Tailwind v4) rapuh saat diproses ulang oleh Vite HMR. Diperbaiki dengan memindahkan Google Fonts ke `<link>` tag di `index.html`, menghapus total `@import url(...)` dari CSS.
- **`Failed to resolve import "./App.css"`** muncul setelah fix di atas: sisa baris `import "./App.css";` dari debugging Fase 2 tidak pernah dihapus, padahal filenya sudah tidak ada lagi (styling sudah pindah total ke `index.css`, di-import sekali di `main.tsx`). Diperbaiki dengan menghapus baris import tsb dari `App.tsx`.
- **Halaman Bagian E Fase 4 (`PermitRecordsPage`/`PermitRecordFormPage`/`PermitRecordDetailPage`) ditulis awal berdasarkan draf walkthrough yang menebak nama fungsi/field tanpa verifikasi ke kode asli**, menghasilkan banyak error TS "no exported member" (`listPermitRecords` vs `getPermitRecords`, `softDeletePermitRecord` vs `deletePermitRecord`, `listPermitTypes` vs `getActivePermitTypes`, `authStore.user` vs `authStore.currentUser`, field `PermitRecordFormInput` camelCase-Inggris vs campuran Indonesia yang sebenarnya dipakai — `nomorIzin`/`namaPemohon`/`tanggalTerbit`/dst, dan `DynamicFieldInput` diasumsikan default export padahal named export). Diperbaiki dengan menulis ulang ketiga halaman berdasarkan isi `types.ts`/`service.ts` yang sebenarnya, bukan dokumen walkthrough lama. **Pelajaran: jangan pernah menebak signature fungsi/field dari dokumen perencanaan lama — selalu verifikasi ke kode aktual sebelum menulis halaman baru.**
- **`Cannot find module '../../permit-status/service'`**: draf kode modul `permit-status` sempat hanya ada sebagai teks yang disetujui, belum benar-benar disimpan sebagai file `.ts` di komputer. Diperbaiki dengan benar-benar membuat file `types.ts`/`repository.ts`/`service.ts` di `src/modules/permit-status/`.
- **ESLint `react-hooks/set-state-in-effect` kena lagi di `PermitRecordFormPage`**: pola `useEffect(() => setForm(...), [detail])` untuk mengisi form dari data hasil query saat mode edit ditolak rule yang sama seperti kasus Fase 3. Diperbaiki dengan pola berbeda dari Fase 3 (bukan cuma pindah ke `useQuery`, karena datanya memang perlu ditransformasi sebelum jadi initial state): split komponen jadi `PermitRecordFormPage` (luar, menunggu query `detail` selesai) yang me-render `PermitRecordFormInner` (dalam, menerima `initialForm` sebagai prop) dengan **`key={id ?? "new"}`** — key ini membuat React mount ulang total komponen dalam tiap kali `id` berganti, sehingga `useState(initialForm)` cukup jadi inisialisasi biasa tanpa `useEffect` sama sekali. **Pola ini jadi referensi untuk kasus serupa di fase berikutnya**: kalau perlu inisialisasi state dari hasil query yang butuh transformasi data, pakai key-remount, bukan `useEffect`+`setState`.
- **Menu navigasi ke halaman baru tidak muncul** meski routing `App.tsx` untuk `/permit-records` sudah benar sejak awal ditulis: `AppLayout.tsx` `navItems` belum didaftarkan link ke halaman tsb. Diperbaiki dengan menambah item ke array `navItems` (lihat Changed).
- **`forbidden path ... not allowed on the scope for allow-exists`** saat membuat folder izin: scope plugin `fs` Tauri v2 bersifat statis (didaftarkan di capabilities), sedangkan `storage_root` dipilih bebas oleh user dan baru diketahui saat runtime. Diperbaiki dengan command Rust `grant_storage_scope` (`FsExt::fs_scope().allow_directory(path, true)`), dipanggil dari `SetupStoragePage` dan tiap app dibuka. Scope dinamis tidak persisten antar restart.
- **`fs.rename not allowed`** saat rename folder: `fs:default` tidak mencakup command `rename` (dan `copy-file`). Ditambahkan `fs:allow-rename` dan `fs:allow-copy-file` di capabilities.
- **`dialog.confirm not allowed. Command not found`** pada dialog konfirmasi: `confirm()` bawaan browser gagal begitu `@tauri-apps/plugin-dialog` dipakai di bundle (diduga plugin mengalihkannya lewat IPC). Diperbaiki dengan memakai `confirm()` dari plugin secara eksplisit. Tombol Hapus di daftar data izin (yang jalan di Fase 4) ikut terdampak dan ikut diperbaiki.
- **`openPath` dari plugin opener tidak bisa dipakai untuk path bebas**: `opener:default` tidak mencakup `allow-open-path` dan scope-nya statis. Diperbaiki dengan command Rust `open_in_default_app`.
- **`react-hooks/set-state-in-effect` kena untuk ketiga kalinya** di `App.tsx` (pola `useEffect` + `checkBoot()` untuk boot flow). Diperbaiki dengan `useQuery` (`useBootStatus`).
- **Regresi kecil di `DynamicFieldInput`**: checkbox tidak punya `id` (klik label tidak mencentang), dan input bertipe decimal ditolak browser untuk nilai pecahan karena `<input type="number">` tanpa `step`. Diperbaiki dengan `id` pada checkbox dan `step="any"` untuk decimal.
- **Tombol selain `btn-primary` tampil seperti teks polos**: preflight Tailwind v4 menghapus border/background bawaan `<button>` dan mengubah kursor jadi panah. Ditambah varian `btn-secondary`/`btn-danger` dan aturan kursor di `@layer base`.
- **`custom_field_options` sempat didesain hard delete**: direvisi jadi soft delete (`is_active`) sebelum pernah dipakai pengguna sungguhan, karena `custom_field_values.value_text` menyimpan string mentah, bukan foreign key — kehilangan baris opsi berarti kehilangan makna data historis. Pola sama dengan alasan `permit_records` memakai soft delete.
- **Label field opsional di form data izin menampilkan "0"**: `is_required` bertipe `number` (0/1), bukan `boolean`. Ekspresi React `{kondisi && <Elemen/>}` merender angka `0` sebagai teks literal kalau `kondisi` itu falsy tapi bukan `false`/`null`/`undefined`. Diperbaiki dengan `Boolean(def.is_required)`.
- **Nilai `select`/`multiselect` tampil JSON/value mentah (`["baru"]`) di halaman detail**: `formatCustomValue` tidak punya penanganan untuk dua tipe itu. Ditambah `getAllOptionsForDefinitions` untuk mencocokkan value ke label aslinya.
- **"Rendered more hooks than during the previous render"** di `PermitRecordDetailPage`: 3 hook baru (`useMemo`/`useQuery`) sempat ditaruh setelah `if (isLoading)`/`if (!record)` — pelanggaran Rules of Hooks. Diperbaiki dengan memindahkan semua hook ke atas, sebelum early return mana pun.
- **Beberapa kesalahan di test, bukan di kode produksi**: dua kali salah hitung nomor placeholder SQL di `searchQuery.test.ts`, dan helper `dateInDays` di `expiry.test.ts` salah zona waktu (`toISOString()` mengonversi ke UTC, tengah malam WIB jadi mundur satu hari). Di semua kasus ini kode produksi sudah benar; yang diperbaiki hanya assertion/helper test. **Pelajaran: saat test gagal, cek dulu di sisi mana bug-nya sebelum "memperbaiki" kode produksi yang sebenarnya sudah benar.**
- **`vi.mock` factory untuk `pathExists` sempat tidak lengkap** (lupa menambah `pathExists: vi.fn()` ke objek yang dikembalikan), menyebabkan `.mockResolvedValue` gagal karena memanggil implementasi asli, bukan mock.
